# 枚举配置页 — 设计规格与实现记录（v0.1）

> 本文档在仓库内的位置：`frontend/docs/acceptance-enum-config-frontend.md`。  
> 它保存本轮实现所依据的 v0.1 设计/验收规格，并记录已经落地的前端接入事实。  
> 本文档不是验收结论。A–H 仍由独立测试判定，实现方不标记 PASS。  
> 实际 API 连通性未在本环境核验。用户电脑上未推送的本地改动不在本记录范围内。

## 实现记录

- 起始提交：`4a755da0c09e0f798abeb759c53addcd809a854c`（与当时 `origin/main` 相同）。
- 页面入口：主导航「枚举配置」。应用没有 React Router，路由是壳层视图 `enums`。
- 深链：`?view=enums` 打开本页；`?enum={name}` 选中对应枚举。示例：`/?view=enums&enum=food_state`。
- 分层：`pages/enums` → `features/enum-config` → `entities/enum` → `shared/api`。
- 弹窗：沿用 `components/Dialog`。尺寸只有两档：`size="sm"` 为原默认宽度，`size="lg"` 为原 `wide` 宽度。没有 `md`。追加表单使用 `sm`。
- 可写性只看响应里的 `editable`、最新一次列表是否带 `file_error`，以及取值数量是否小于 100。代码不使用可写枚举白名单做运行时闸门。
- 契约核对：当前后端就是 `GET /api/enums`、`GET /api/enums/{name}`、`POST /api/enums/{name}/values`（201）。成功体没有 `trace_id`，追踪在响应头 `X-Trace-Id`。错误体为 `{ ok:false, error, detail, trace_id, errors? }`。
- 本轮没有改后端，没有加类别 / 场景 / 加热组管理，也没有把新枚举值接到上传页。

## 1. 目标与边界

在图搜图管理端提供「枚举配置」：查询全量枚举和单个枚举，并对 `editable=true` 的枚举追加新值。已有取值只读。没有编辑、删除、排序、停用。

| 方法 | 路径 | 成功 |
|------|------|------|
| GET | `/api/enums` | `{ ok: true, enums: EnumItem[], file_error?: string }` |
| GET | `/api/enums/{name}` | `{ ok: true, enum: EnumItem }` |
| POST | `/api/enums/{name}/values` | **201** `{ ok: true, enum: EnumItem }` |

```
EnumItem  = { name, label, description, editable, values: EnumValue[] }
EnumValue = { value, label, description }
```

POST 正文只有 `{ value, label, description }`。`description` 缺省按空字符串提交。

静态说明里的可追加四类是 `source_type` / `license` / `food_state` / `food_processing`，只读七类是 `category_domain` / `name_kind` / `label_status` / `scene_origin` / `distance` / `model_status` / `review_status`。这只是对照，不是前端闸门。

| 字段 | 规则 |
|------|------|
| `value` | trim 后长度 1–32；匹配 `^[a-z][a-z0-9_]*$` |
| `label` | trim 后长度 1–64 |
| `description` | 默认空字符串；最长 256；不额外 trim |
| 每类 `values` | 最多 100 |

## 2. 布局

桌面为左列表、右详情。窄屏（最大宽度 760px，与壳层相同）改为单栏：先列表，选中后进入详情，详情提供「返回列表」。`file_error` 或暂停追加的告警在分栏之外，两种宽度都看得到。

未选中时详情为「请选择左侧枚举」。列表为空时走空态，不提供追加。选中只读枚举时值表仍显示，追加按钮不可用，并说明只读。

## 3. 状态与追加

- 进入页面请求 `GET /api/enums`。加载中只显示加载指示，不填假数据。
- 列表失败时保留已成功展示的数据，并显示错误码、说明、追踪号和重试。
- 选中后先用列表里的该项展示，再请求 `GET /api/enums/{name}`。过期的详情响应丢弃。详情失败不清空列表和已显示的值。详情响应不读取 `file_error`。
- 每次 POST 前重新请求 `GET /api/enums`。文件异常、不可追加、已满 100、或这次校验失败时，不发 POST，并保留表单输入。过期的干净列表不能清掉更新的告警。
- 提交过程锁定打开弹窗时的枚举名，禁止重复点击，并暂时不能关闭弹窗。
- POST 不自动重试。
- HTTP 201 后立刻用返回的 `enum` 更新该项，再请求详情核对。核对失败时提示「已写入，刷新未完成，请手动刷新」，并禁止把同一个 `value` 再追加一次。这种情况不叫写入失败。
- 没有明确错误体的超时或网络失败，先做一次列表核查。核查失败则继续禁止该取值。查到已存在时说明已存在并刷新列表，不声称这就是本次写入。只有新鲜查询确认不存在且文件健康、枚举仍可追加时，才允许手动再提交。

## 4. 错误展示

展示使用实体层映射后的结果，不在页面里散落错误码分支。

| 场景 | 参考 HTTP | 页面行为 |
|------|-----------|----------|
| `ENUM_NOT_EDITABLE` | 403 | 该项改为不可追加，表单不能再提交 |
| `ENUM_VALUE_EXISTS` | 409 | 取值字段报重复，其它输入保留 |
| `VALIDATION_ERROR` | 422 | 有 `errors` 时按字段显示，否则显示 `detail` |
| `ENUM_FILE_INVALID` | 503 | 告警并禁止追加 |
| `ENUM_FILE_WRITE_FAILED` | 500 | 提示写入失败，不自动重试 |
| 网络 / 超时 / 无明确错误体 | — | 不自动重试，先核查再决定能否手动提交 |
| 其它 | — | `detail`、追踪号；重试只重放 GET |

成功追踪读 `X-Trace-Id`。错误追踪优先用响应体里的 `trace_id`。

## 5. 验收条目（未执行）

### A. 入口与壳

| ID | 标准 |
|----|------|
| A1 | 管理导航可见「枚举配置」，点击进入本页。 |
| A2 | 页标题为枚举配置；窄屏下详情可返回列表。 |
| A3 | 没有编辑 / 删除 / 排序 / 停用，也没有类别、场景、加热组等假配置区。 |

### B. 列表与详情

| ID | 标准 |
|----|------|
| B1 | 进入页触发 `GET /api/enums`，加载中有明确指示。 |
| B2 | 成功后每项可见 label、name、值数量，以及由 `editable` 决定的可追加 / 只读。 |
| B3 | 选中后展示 name、label、description、editable 和只读值表。 |
| B4 | 空列表走空态；未选中有占位提示。 |
| B5 | 列表失败可见错误码、说明、追踪号，可重试，不伪造数据。 |
| B6 | 详情失败不清空列表和已有详情。 |
| B7 | 快速切换选中时，过期响应不覆盖当前选择。 |

### C. `file_error` 与禁写

| ID | 标准 |
|----|------|
| C1 | 200 且含 `file_error` 时顶部有告警。 |
| C2 | 告警未解除时不能追加。 |
| C3 | 切换选中项不能解除禁写。 |
| C4 | 只有更新的、不带 `file_error` 的成功列表能恢复可写入口，并且仍受 `editable` 约束。 |
| C5 | 不从详情响应读取未声明的 `file_error`。 |

### D. 可写性与追加

| ID | 标准 |
|----|------|
| D1 | `editable === false` 时不能追加。 |
| D2 | 可追加、文件健康、未满 100 时可以打开表单。 |
| D3 | 已有 100 个值时禁止追加并提示上限。 |
| D4 | 非法 value / label / description 不发 POST。 |
| D5 | POST 正文只有这三个字段，说明可以为空字符串。 |
| D6 | 提交中不能重复点击，并有提交中状态。 |
| D7 | 201 用返回的 enum 更新界面，并再次 GET。 |
| D8 | 201 后刷新失败不叫写入失败；同一 value 不能再追加；可以手动刷新。 |
| D9 | POST 失败不自动重试。 |
| D10 | 网络不确定时先核查，再允许手动重试。 |

### E. 错误码

| ID | 标准 |
|----|------|
| E1 | 403 `ENUM_NOT_EDITABLE`：追加不可用，并有说明。 |
| E2 | 409 `ENUM_VALUE_EXISTS`：value 字段报错，改完可再提交。 |
| E3 | 422 `VALIDATION_ERROR`：字段或 detail 提示正确。 |
| E4 | 503 `ENUM_FILE_INVALID`：告警并禁写。 |
| E5 | 500 `ENUM_FILE_WRITE_FAILED`：失败提示，无自动重试。 |
| E6 | 未知错误有追踪号；GET 可重试，POST 不自动重试。 |

### F. 无障碍与键盘

| ID | 标准 |
|----|------|
| F1 | 列表和主要按钮可用键盘到达并激活。 |
| F2 | 弹窗打开时焦点进入取值；关闭后回到触发按钮。Esc 可关闭。提交过程中不能关掉弹窗。 |
| F3 | 校验错误通过 `aria-invalid` 和 `aria-describedby` 关联到字段。校验失败时提交按钮仍可聚焦。 |

### G. 分层与范围

| ID | 标准 |
|----|------|
| G1 | 依赖方向为 pages → features → entities → shared。 |
| G2 | API 与错误映射集中在实体层。 |
| G3 | 没有扩展模型管理或审核管理，也没有承诺上传页可选新值。 |
| G4 | 复用现有 Dialog、EmptyState、管理页按钮和表单样式。 |

### H. 边界

| ID | 标准 |
|----|------|
| H1 | `a` 和 32 个小写字母有效；空白、33 字符、`1abc`、`Abc`、`a-b`、中文无效；` a_b ` 按 `a_b` 提交。 |
| H2 | 名称 trim 后 1 和 64 字符有效，0 和 65 无效。说明默认空字符串，256 有效，257 无效，不额外 trim。 |
| H3 | 99 条可追加；已有 100 条不发 POST。 |
| H4 | 提交前的健康检查失败、返回 `file_error`、变为只读或达到 100 条时不发 POST，并保留输入。过期的干净响应不能清掉新告警。 |
| H5 | 列表非空但当前没有值时，详情显示「暂无枚举值」；其它闸门通过时仍可追加。 |
| H6 | 核查 GET 失败时继续阻止同一 value。查到已存在则告知已存在并刷新，不伪称本次写入。只有新鲜查询确认不存在且健康后才允许手动重试。 |
| H7 | 提交目标在打开弹窗时锁定。成功用返回的 enum 更新该项；失败保留输入。 |

## 6. 独立测试建议

1. 用仓库里的前端和现有后端启动，不要依赖某一台临时环境里的绝对路径。
2. 打开 `/?view=enums`，确认导航、列表请求、桌面双栏和窄屏返回。
3. 对只读枚举确认不能追加；对 `editable=true` 且数量未满的枚举走一遍合法追加和非法输入。
4. 用损坏的枚举文件或接口桩覆盖 `file_error`、403、409、422、500、503，以及断网 / 超时。
5. 上述条目均未在本次实现中作最终验收。
