# 食材图像工作台

React + TypeScript + Vite 前端。接入 Global 图像搜索，支持批量查询与结果下载；数据管理功能保留独立页面，入库与管理接口待接入。后端新增图片下载接口，用于浏览器无法跨域读取第三方图片时的回退。

## 本地运行

需要 Node.js 22.12+ 或 24，以及 npm。

```bash
cd frontend
npm install
```

Windows 如因本机 npm 缓存目录权限遇到 `EPERM`，可在 PowerShell 使用临时缓存：`npm.cmd install --cache "$env:TEMP\food-atlas-npm-cache"`，无需修改全局 npm 配置。

将 `.env.example` 复制为 `.env.local`，按需调整后端地址，然后启动：

```bash
npm run dev -- --host 0.0.0.0
```

打开终端显示的地址，默认 `http://localhost:5173`。后端需单独启动；开发服务器默认将 `/api` 转发到 `http://127.0.0.1:8320`，与当前后端 Compose 的端口映射一致。

| 配置 | 用途 |
| --- | --- |
| `VITE_API_PROXY_TARGET` | Vite 开发代理的后端地址，修改后需重启开发服务器 |
| `VITE_API_BASE_URL` | 可选的浏览器 API 地址；留空使用同源 `/api`，跨域需要后端允许 CORS |

界面中的接口设置可覆盖浏览器 API 地址，保存在当前浏览器的 `localStorage`。`VITE_*` 配置会进入前端构建产物，不应包含密钥。

## 当前功能

- 上传查询图片或输入图片 URL，调用已有搜索接口；显示请求状态、错误与空结果。
- 切换到“批量搜索”后可添加最多 30 张查询图片，每张不超过 15 MB。前端逐张调用文件搜索接口，显示各自进度、失败原因和结果；首张成功后自动展示结果，后续可点击队列中的“查看结果”切换。支持停止、继续和重试未完成任务，单项失败不影响后续图片。
- 支持网格／列表切换，展示结果图片和后端返回的相似度；图片按需加载，原图加载失败时按 large、medium、small、其他缩略图依次回退，详情弹窗按检索、预览、来源分区显示。Global 搜索阶段不会提前验证所有图片；仅开启 embedding 相似度过滤时，后端才按需获取图片计算分数。
- 当前结果集支持本地分页；只有接口提供类别时才能按类别筛选，不会从标题推测类别。
- 支持逐张选择、选择本页、选择全部结果和清空选择。跨页和切换网格／列表时保留选择；新的搜索或切换另一张查询图片的结果时清空选择，避免混合不同查询的结果。
- 点击“批量下载”可选择 ZIP 或保存到指定目录；按进度显示成功、失败记录，可停止或仅重试失败项。原图无法获取时按 large、medium、small、其他缩略图依次尝试，每批图片数据合计上限 200 MB，并附带 `results.json` 文件记录来源、相似度和失败原因。

### 保存位置与图片来源

支持目录选择的 Chrome、Edge 等浏览器可在 **HTTPS 或 localhost / 127.0.0.1** 页面使用“保存到指定目录”；实际支持情况由页面检测。普通 HTTP 局域网地址通常无法使用目录选择，仍可下载 ZIP。浏览器需要用户主动选择并授予目录访问权限；页面仅能显示目录名称，无法读取或展示完整本地路径。

每次目录下载会在所选位置新建独立的 `images-…` 子目录，避免覆盖已有文件。ZIP 的保存位置由浏览器下载设置决定；需要每次指定位置时，可启用浏览器的“下载前询问保存位置”。ZIP 下载成功表示文件已交给浏览器，请在下载列表中确认保存结果。

下载先尝试直接读取来源图片，跨域等原因失败时通过 `GET /api/images/download` 回退，再尝试缩略图。后端仅下载 HTTP(S)、80/443 端口的公网图片，每张最多 15 MB，检查每次重定向及实际图片格式；不访问内网、回环或元数据地址。代理不能绕过源站的登录、授权或防盗链限制；失败项仍可打开来源手动保存。

**使用代理功能需要重启包含本次代码的后端。** 现有旧镜像不会自动获得新接口，需重新构建或更新为包含新代码的镜像。数据管理相关后端功能未新增。

### 图片数据

左侧窄栏是筛选工具，右侧宽区显示图片；宽屏下两边各自滚动，图片区的页头和翻页始终可见，窄屏（≤ 900 px）筛选栏收在页头里，点「展开筛选」打开。筛选全部由 `GET /api/images` 在服务端完成：

- 关键词（类别名、标签、图片链接或 ID 的子串，停顿 300 ms 后请求）、场景、标注状态、向量库状态（待同步或没有向量）、标签（`tag`，与标签完全一致，输入时可带卡片上显示的 `#`）。
- 类别树：按类别筛选时包含它的所有下级（`category_id`）。树为虚拟列表，只渲染可见行，上千个类别也流畅；可搜索名称、编码和别名（多个词时其余词可匹配上级类别名，命中项连同上级一起显示），支持方向键、Enter 等键盘操作。每个类别显示图片数（`GET /api/categories` 的 `image_count` 按子树汇总，不分场景，打开页面和在编辑弹窗里改动后重新读取）；可隐藏没有图片的类别、显示停用类别，并保留最近用过的类别。
- 卡片上的类别和标签可直接点击筛选；右侧页头列出生效的筛选，可逐个清除或一次清空。「未标注」即没有类别，和类别筛选互斥，选择其一时自动取消另一个并提示。
- 每页 24 / 48 / 96 张，可跳到指定页；大图、小图、列表三种展示方式。展示方式、每页数量、类别树选项和最近用过的类别保存在当前浏览器的 `localStorage`；筛选条件和页码在切到「上传与导入」「入库任务」再回来时保留，刷新或打开其他页面后恢复默认。
- 批量操作：卡片和列表行可以勾选（按住 Shift 连选），也可以「本页」全选或「选择全部 N 张」筛选结果（分页读取，一次最多 1000 张）。翻页时保留勾选，换筛选条件时清空，避免把看不到的图片带进批量操作。
  - 批量修改：类别、标注状态、标签（添加 / 移除 / 替换 / 清空）、描述和六个食物字段，每项默认「不修改」，只有设了的才写入。逐张调用 `PATCH /api/images/{id}`（同时 3 个），规则和单张编辑一样：清空类别即未标注，设了类别而标注状态不修改时记为已核验；没有类别的图片不改标注状态。添加、移除标签先读每张图片当前的标签再改，不会覆盖别人刚加的。
  - 批量删除：确认时显示数量和缩略图，20 张及以上要输入「删除」；逐张调用 `DELETE /api/images/{id}`，已经删除的算成功。
  - 进行中可以停止（已发出的请求会完成），结束后列出失败、跳过和有备注的图片及原因，可以只重试失败的或继续未处理的；全部成功时自动关闭并提示。结束后图库和类别数量重新读取。
- 缩略图和原图：先用接口给的 `thumb_url` / `original_url`；打不开时（mock 存储的占位域名 `cdn.example.local`、私有桶、CDN 故障）改用 `GET /api/images/{id}/file?variant=thumb|original` 从后端读回，并记住打不开的域名，之后的图片直接走后端，不再逐张等失败。图库卡片和列表、图片编辑、批量操作、入库任务、待清理图片和检索结果（本库命中的）都是这样（`entities/image` 的 `StoredImage`）。

数据管理包括图片数据、上传与批量导入、入库任务、食材管理、场景管理和枚举配置。「食材管理」就是类别树（`GET`/`POST /api/categories`、`PATCH`/`DELETE /api/categories/{id}`，可用 `?view=categories&category=<id>` 直接打开某个类别）：每个食材都是某个类别域（食材、菜品、甜点烘焙、饮品）下的类别，名称、别名、菜系、加热组都在这里维护。移动类别或改菜系后，后端随即重算标在它和下级类别上的图片的场景归属并同步到向量库，保存提示里说明有多少张变了；没能同步完的（检索服务未就绪、写入失败）用弹窗说明原因，后台对账会补上。页面不使用模拟数据伪装搜索或入库成功。

「入库任务」的「待清理图片」页签列出已从数据库删除、向量和文件还没删掉的图片（`GET /api/image-deletions`，最早删除的在前，最多列 50 张），「立即清理」逐批调用 `POST /api/image-deletions/process`（每批 50 条，有进展才继续，一次最多 10 批）；清理失败的留在队列里，在列表里写明原因，后台对账会定时重试。检索服务未就绪时按钮不可用。

### 信息提示（统一控件）

操作结果统一由一个控件提示：根组件里只挂一个 `<StatusOverlay />`（`src/shared/ui`），各页面发信号激活它，不再各自渲染提示条：

```ts
import { notify } from '../shared/ui'

notify.success('已保存。')                                              // 轻提示
notify.error(reason, { title: '保存失败' })                              // 弹窗
notify.warn('部分图片未添加', { details: issues })                      // 弹窗，details 逐条列出
notify.success('已保存。', { action: { label: '去同步', onClick } })     // action：onClick 或 href
```

- 成功（`success`）和普通提示（`info`）是顶部居中的**轻提示**：不挡操作、不抢焦点，可以同时显示最多 3 条；成功约 2.4 秒、普通提示约 3.6 秒后自动关闭，文字越长显示越久（最长 8 秒），鼠标停在上面时暂停，也可以点 × 关掉。有对话框打开时，轻提示显示在这个对话框里，不会被遮罩挡住。
- 警告（`warn`）和错误（`error`）用**弹窗**：模态 `<dialog>`，叠在已打开的对话框之上，看过、点「知道了」才关闭，原因和 trace_id 不会一闪而过。Esc、右上角关闭也会关掉它，点空白处也会关（`closable: false` 时不会）；关闭后焦点回到触发它的控件。同一时间只显示一个弹窗，后来的排在后面依次显示，相同的只显示一次。
- 可用 `duration` 改显示时长，`0` 表示不自动关闭。
- 字段校验（输入框下的红字）、加载失败加重试、入库按钮旁「为什么还不能开始」这类跟某个位置绑定的状态仍然显示在原处，不进提示。

## 已有接口约定

| 方法与路径 | 请求 |
| --- | --- |
| `POST /api/predict/searchImage_file` | `multipart/form-data`，文件字段为 `file` |
| `POST /api/predict/searchImage_url` | JSON：`{"img_url":"https://example.com/image.jpg"}` |
| `GET /api/images/download` | Query：`url`，返回经验证的图片字节和实际图片 MIME 类型 |

响应为 `{ "result": [...], "trace_id": "..." }`，也兼容 `result` 为包含 `results` 数组的对象。图片字段为 `image_url`，分数为 `similarity`（缺失时不显示虚构分数）；详情和缩略图来自 `details`。Global 搜索返回的候选结果不等同于已入库图片。

## 验证与部署

```bash
npm test
npm run test:e2e
npm run build
npm run preview
```

浏览器测试使用本机安装的 Google Chrome，自动启动或复用 `127.0.0.1:5173` 的开发服务。交互测试覆盖 URL/文件与批量搜索、多选与批量下载、代理回退、详情、筛选分页、错误与取消、导入队列、食材管理（类别树）及手机布局。桌面与移动端截图输出到 `test-results/`，失败时保留 trace。测试中的网络响应使用受控模拟，目录选择使用内存替身，不访问真实后端或用户的保存目录；实际页面请求真实后端。构建输出为 `dist/`，可部署到静态 Web 服务。

生产环境需要 Web 服务将 `/api` 反向代理到后端，或在构建前设置 `VITE_API_BASE_URL` 并配置后端 CORS。Vite 的 `server.proxy` 仅用于开发，`npm run preview` 和静态产物不会自动代理 `/api`。环境变量在构建时读取，部署后修改需重新构建；接口设置也可在浏览器内覆盖。
