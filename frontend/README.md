# 食材图像工作台

React + TypeScript + Vite 前端。接入 Global 图像搜索，支持批量查询与结果下载；数据管理功能保留独立页面，入库与管理接口待接入。后端新增图片下载接口，用于浏览器无法跨域读取第三方图片时的回退。

## 本地运行

需要 Node.js 22.12+ 或 24，以及 npm。

```bash
cd frontend
npm install
```

Windows 如因本机 npm 缓存目录权限遇到 `EPERM`，可在 PowerShell 使用临时缓存：`npm.cmd install --cache "$env:TEMP\food-atlas-npm-cache"`，无需修改全局 npm 配置。

将 `.env.example` 复制为 `.env.local`，按需调整后端地址，然后启动：

```bash
npm run dev -- --host 0.0.0.0
```

打开终端显示的地址，默认 `http://localhost:5173`。后端需单独启动；开发服务器默认将 `/api` 转发到 `http://127.0.0.1:8320`，与当前后端 Compose 的端口映射一致。

| 配置 | 用途 |
| --- | --- |
| `VITE_API_PROXY_TARGET` | Vite 开发代理的后端地址，修改后需重启开发服务器 |
| `VITE_API_BASE_URL` | 可选的浏览器 API 地址；留空使用同源 `/api`，跨域需要后端允许 CORS |

界面中的接口设置可覆盖浏览器 API 地址，保存在当前浏览器的 `localStorage`。`VITE_*` 配置会进入前端构建产物，不应包含密钥。

## 当前功能

- 上传查询图片或输入图片 URL，调用已有搜索接口；显示请求状态、错误与空结果。搜索目标有三个，单张和批量共用：**自建库**（默认，`POST /api/search`）、**现网 Global**（`POST /api/search/global/*`）、**业务搜图**（`POST /api/search/auto/*`：先查自建库，服务端开启菜谱识别时同时识别查询图里的菜名，作为一张标「菜谱识别」的结果卡排在自建库结果之后——它没有图片，不能勾选和下载；两者都没有结果时按开关用现网 Global 兜底，兜底来的结果卡标「Global」，返回数量 1–20 对自建库和 Global 都生效）。
- 切换到“批量搜索”后可添加最多 30 张查询图片，每张不超过 15 MB，对队列里的每张图使用所选的搜索目标：自建库走多图搜索接口 `POST /api/search/batch/files`（每次请求最多 5 张，整批共用场景和拒识阈值，某张图读不出只影响它自己）；现网 Global、业务搜图逐张调用各自的文件搜索接口。显示各自进度、失败原因和结果；首张成功后自动展示结果，后续可点击队列中的“查看结果”切换。支持停止、继续和重试未完成任务，单项失败不影响后续图片；「停止」立即取消前端等待，服务端已开始的检索可能继续；改了目标、场景或阈值后，已完成的图片保留原结果，点「全部重新搜索」按当前设置重跑整个队列。
- 支持网格／列表切换，展示结果图片和后端返回的相似度。网格和列表只加载缩略图：自建库结果用 512px WebP 缩略图（地址打不开时由后端读出），现网结果按 large、medium、small 依次回退，缩略图都打不开才用原图。点开图片进入详情才加载原图：先显示列表里已加载的缩略图并提示「正在加载原图」，原图加载完再原位换上；原图打不开时保留缩略图并说明。详情弹窗按检索、预览、来源分区显示。图片数据的「图片标注」同样先显示缩略图、再换成原图（`entities/image` 的 `ProgressiveImage`）。Global 搜索阶段不会提前验证所有图片；仅开启 embedding 相似度过滤时，后端才按需获取图片计算分数。
- 结果卡分行标注，避免把含义相近的值混在一起：自建库结果第一行是类别（也是卡片标题），下面是场景标签（没有映射时显示「未映射」）和标签；现网结果第一行是结果标题，下面是来源站点。下载按钮在第一行右侧；只有检索场景输出加热信息时，卡片底部才多一行加热组和食物状态。列表视图的列和它一致。
- 当前结果集支持本地分页；只有接口提供类别时才能按类别筛选，不会从标题推测类别。
- 支持逐张选择、选择本页、选择全部结果和清空选择。跨页和切换网格／列表时保留选择；新的搜索或切换另一张查询图片的结果时清空选择，避免混合不同查询的结果。
- 点击“批量下载”可选择 ZIP 或保存到指定目录；按进度显示成功、失败记录，可停止或仅重试失败项。原图无法获取时按 large、medium、small、其他缩略图依次尝试，每批图片数据合计上限 200 MB，并附带 `results.json` 文件记录来源、相似度和失败原因。

### 保存位置与图片来源

支持目录选择的 Chrome、Edge 等浏览器可在 **HTTPS 或 localhost / 127.0.0.1** 页面使用“保存到指定目录”；实际支持情况由页面检测。普通 HTTP 局域网地址通常无法使用目录选择，仍可下载 ZIP。浏览器需要用户主动选择并授予目录访问权限；页面仅能显示目录名称，无法读取或展示完整本地路径。

每次目录下载会在所选位置新建独立的 `images-…` 子目录，避免覆盖已有文件。ZIP 的保存位置由浏览器下载设置决定；需要每次指定位置时，可启用浏览器的“下载前询问保存位置”。ZIP 下载成功表示文件已交给浏览器，请在下载列表中确认保存结果。

下载先尝试直接读取来源图片，跨域等原因失败时通过 `GET /api/images/download` 回退，再尝试缩略图。后端仅下载 HTTP(S)、80/443 端口的公网图片，每张最多 15 MB，检查每次重定向及实际图片格式；不访问内网、回环或元数据地址。代理不能绕过源站的登录、授权或防盗链限制；失败项仍可打开来源手动保存。

**使用新增接口需要重启包含本次代码的后端。** 现有旧镜像不会自动获得图片下载代理、多图搜索或配置导入接口，需重新构建或更新为包含新代码的镜像。

### 图片数据

左侧窄栏是筛选工具，右侧宽区显示图片；宽屏下两边各自滚动，图片区的页头和翻页始终可见，窄屏（≤ 900 px）筛选栏收在页头里，点「展开筛选」打开。筛选全部由 `GET /api/images` 在服务端完成：

- 关键词（类别名、标签、图片链接或 ID 的子串，停顿 300 ms 后请求）、场景、标注状态、向量库状态（待同步或没有向量）、标签（`tag`，与标签完全一致，输入时可带卡片上显示的 `#`）。
- 类别树：按类别筛选时包含它的所有下级（`category_id`）。树为虚拟列表，只渲染可见行，上千个类别也流畅；可搜索名称、编码和别名（多个词时其余词可匹配上级类别名，命中项连同上级一起显示），支持方向键、Enter 等键盘操作。每个类别显示图片数（`GET /api/categories` 的 `image_count` 按子树汇总，不分场景，打开页面和在编辑弹窗里改动后重新读取）；打开时类别域已展开。图库里已有图片时，默认隐藏没有图片的类别（含下级也没有的，复选框旁显示个数；按它们筛选什么也找不到），可取消；还没有任何图片时全部列出。可显示停用类别，并保留最近用过的类别。用拼音输入时，确认候选字的回车只上屏文字，不会选中类别。
- 卡片从上到下：图片（左上角是勾选框，需要处理时右上角标「待同步」或「没有向量」）、类别和标注状态、描述的开头（没有描述时显示图片 ID 的前 8 位）；大图另有一行所属场景和标签，小图只到描述为止。同一行的卡片底部对齐。
- 卡片上的类别和标签可直接点击筛选；右侧页头列出生效的筛选，可逐个清除或一次清空。「未标注」即没有类别，和类别筛选互斥，选择其一时自动取消另一个并提示。
- 每页 24 / 48 / 96 张，可跳到指定页；大图、小图、列表三种展示方式。展示方式、每页数量、类别树选项和最近用过的类别保存在当前浏览器的 `localStorage`；筛选条件和页码在切到「上传与导入」「入库任务」再回来时保留，刷新或打开其他页面后恢复默认。
- 批量操作：卡片和列表行可以勾选（按住 Shift 连选），也可以「本页」全选或「选择全部 N 张」筛选结果（分页读取，一次最多 1000 张）。翻页时保留勾选，换筛选条件时清空，避免把看不到的图片带进批量操作。
  - 批量修改：类别、标注状态、标签（添加 / 移除 / 替换 / 清空）、描述和六个食物字段，每项默认「不修改」，只有设了的才写入。逐张调用 `PATCH /api/images/{id}`（同时 3 个），规则和单张编辑一样：清空类别即未标注，设了类别而标注状态不修改时记为已核验；没有类别的图片不改标注状态。添加、移除标签先读每张图片当前的标签再改，不会覆盖别人刚加的。
  - 批量删除：每批最多 500 张，选多了先提示分批删除（勾选保留，可减少后再删）；确认时显示数量和缩略图，20 张及以上要输入「删除」；逐张调用 `DELETE /api/images/{id}`，已经删除的算成功。
  - 进行中可以停止（已发出的请求会完成），结束后列出失败、跳过和有备注的图片及原因，可以只重试失败的或继续未处理的；全部成功时自动关闭并提示。结束后图库和类别数量重新读取。
- 缩略图和原图：前端不拼对象键，地址里的目录由后端决定（新入库的图在 SHA-256 前 2 位的分片目录下，如 `original/a3/{id}.jpg`、`thumb/a3/{id}.webp`；更早入库的图仍是 `original/{id}.jpg`），两种地址原样使用。先用接口给的 `thumb_url` / `original_url`；打不开时（mock 存储的占位域名 `cdn.example.local`、私有桶、CDN 故障）改用 `GET /api/images/{id}/file?variant=thumb|original` 从后端读回，并记住打不开的域名，之后的图片直接走后端，不再逐张等失败。图库卡片和列表、图片编辑、批量操作、入库任务、待清理图片和检索结果（本库命中的）都是这样（`entities/image` 的 `StoredImage`）。

数据管理包括图片数据、上传与批量导入、入库任务、食材管理、场景管理和枚举配置。「上传与导入」的待入库队列一次最多 500 张（JPG / PNG / WebP，每张最大 15 MB），逐张调用 `POST /api/index`；接口一次请求最多带 500 个文件。「食材管理」就是类别树（`GET`/`POST /api/categories`、`PATCH`/`DELETE /api/categories/{id}`，可用 `?view=categories&category=<id>` 直接打开某个类别）：每个类别都在某个类别域（食材、菜品、甜点烘焙、饮品、混合、其他）下面，根节点最多六个；混合用于多食材、多菜品、饮品等混合在一起的图像，其他用于暂不归入前五个类别域的图像。名称、别名、菜系、加热组都在这里维护。类别多了以后：

- 「范围」下拉除了类别域，还列出类别域下面的分组（谷物、水产……），选中后表格只显示这个分组，此时「新建类别」默认放在它下面；每行一行高，编码过长时只截掉前面的上级部分，悬停可看完整编码；「使用」列给出分组下级类别上的图片合计；表格在面板里滚动，表头、工具栏和底部计数一直可见。
- 新建、编辑时的「上级类别」是可搜索的树：输入名称、编码或别名直接找到，不输入时逐级展开；编辑时不提供自己和自己的下级。中文名称和已有类别的名称或别名相同时会提示（名称允许重复，提示只为避免重复建）。「创建并继续」保存后留在对话框里，保持同一个上级，接着输入下一个编码。
- 工具栏「下载类别树」打开下载对话框，导出的都是完整类别树（包含停用类别，不受当前搜索、范围、状态筛选或展开折叠影响；类别树尚未加载、刷新失败或为空时按钮不可用）：
  - 数据文件（JSON）：类别总数、树形层级、编码、名称与别名、启停状态、菜系、加热组及引用计数，带 `schema_version: 1` 和 `kind: "category_tree"`。可以编辑后用「上传类别树」导回，也可以作为备份导入另一套库。
  - 文字拓扑图（TXT）：用树形线条画出层级，一行一个类别，带编码、停用标记、菜系、加热组和图片数；对话框里有预览。
  - 图像拓扑图（SVG / PNG）：从左到右一层一列，每个类别域一种颜色，停用的类别是灰色虚线框。SVG 是矢量图，类别再多也清晰；PNG 由浏览器画布生成，类别特别多、超出画布上限时提示改用 SVG。
  - 全部打包（ZIP）：以上四个文件加一份说明。
- 工具栏「上传类别树」选择一个 JSON 文件（下载得到的数据文件，或 `GET /api/categories` 的响应体，可以只保留要改的节点），先调用 `POST /api/categories/import`（`dry_run=true`）显示预览：新建、更新、无变化、有问题各多少，逐项列出变更和原因，以及库里有而文件没列出的类别；点「确认导入」才写入（`dry_run=false`），完成后显示结果并重新读取类别树。按编码匹配；不移动、不改编码、不删除类别。有问题的条目不导入、其余照常；改好文件重新上传即可，已导入的不会重复。

「场景管理」页（`?view=scenes`）分三块：页头一句话说明场景是什么（搜图时可选的范围），以及对全部场景生效的操作（全量同步、下载配置、上传配置、刷新）；左侧是场景列表，每行有图片张数和占图库的比例条；右侧没选场景时说明场景怎么起作用、哪些改动要全量同步，选中后是这个场景的名称、状态和一段由配置生成的说明（搜图时在多少张图片里找、结果显示什么），下面两个页签：「收录规则」（按类别或菜系收录哪些图片，以及类别对应的标签）和「场景标签」（搜索结果「场景标签」一栏显示的标签）。全量同步不属于某个场景，从页头进入（其他页面仍可用 `?view=scenes&sceneTab=sync` 直接打开）。页面上把 `scene_labels` 叫「场景标签」（数据契约里叫场景类别）。

「场景管理」页头同样有「下载配置」「上传配置」：下载的是全部场景及其场景标签、规则（`scene-config-….json`，`kind: "scene_config"`）；上传走 `POST /api/scenes/import`，同样先预览再确认，场景、场景标签按编码匹配，规则按目标（类别编码或菜系）匹配。预览里可勾选「同时删除文件里没有列出的规则和场景标签」（`prune=true`，只作用于文件里出现且显式带 `rules` / `labels` 列表的场景，场景本身从不删除）。全量同步进行时不能上传；导入后需要同步时页面照常提示「去同步」。导入逐项提交，预览不会锁定目录；中途失败时已写入内容保留，页面重新读取配置后可再次上传。导入的规则和格式见[数据契约 §6.8](../docs/image-search-pg-v01-data-contract.md#config-transfer)。

上传标注、图片编辑、批量修改和场景规则选类别用同一个选择器（`features/category-picker`）：不输入时是按层级折叠的类别树（方向键移动，→ / ← 展开、收起，Enter 选中），输入后按名称、别名、编码和路径搜索，命中别名时显示是哪个别名；上传、图片编辑和批量修改还会列出最近选过的类别（保存在当前浏览器）。场景规则可以选停用的类别。

移动类别或改菜系后，后端随即重算标在它和下级类别上的图片的场景归属并同步到向量库，保存提示里说明有多少张变了；没能同步完的（检索服务未就绪、写入失败）用弹窗说明原因，后台对账会补上。页面不使用模拟数据伪装搜索或入库成功。

类别编码可使用大小写字母、数字和下划线，用点分段，并保留输入的大小写；唯一性不区分大小写，例如 `ingredient.HongSu` 和 `Ingredient.hongsu` 不能属于两个类别。仅修改当前类别编码的大小写可以保存。

编辑类别时，更换上级会自动把当前节点编码接到新父级后面；当前节点改编码时，所有后代也按各自的最后一段逐层重新生成完整编码。保存前会预览更新数量和示例，并校验整棵子树的编码冲突与长度。页面只提交一次当前节点的 PATCH，后端在同一事务内更新整棵子树，成功后重新加载完整目录。

「入库任务」的「服务端入库记录」页签列出每个入库文件的结果（`GET /api/index-tasks`）。每条记录是一次上传，不是一张图片：同一张图片重复上传（例如上一次被取消或超时、其实服务端已入库）会多出一条成功记录，标为「重复上传」（`new_image=false`），不计入「新入库图片」；和「图片数据」的数量对照时看「新入库图片」（`counts.succeeded - image_deleted - repeated`）。从图库删除图片不会删除它的入库记录：记录保留（用来追溯哪天入过哪些文件），标为「图片已删除」并可单独筛选；不需要时用「清理图片已删除的记录」（`DELETE /api/index-tasks?image_state=deleted`）、「清空失败记录」（`?status=failed`）或详情里的「删除这条记录」（`DELETE /api/index-tasks/{id}`）处理，都要先确认，只删记录、不动图片。

「模型版本」页（`?view=models`）用来换 embedding 模型：上方显示检索在用的版本、`EMBEDDING_CONFIG` 配置的模型（是否已登记）和图库图片数，并按当前状态给出下一步——登记为新版本（`POST /api/embedding-models`）→ 生成向量（`POST …/{id}/build`，服务端后台进行，页面每 2 秒刷新进度，可停止、续做，没生成的图片列出原因）→ 切换（`POST …/{id}/activate`，原版本保留可切回；缺的图片在 `switch_catch_up_max`（200）张以内时说明切换时会先补上，超过时要勾选「仍然切换」）。版本列表显示每个版本的覆盖率、向量库实际点数不足的提示、权重 hash 和「镜像里没有它的权重」「权重文件被改过」标记，可以生成 / 补齐 / 核对并补齐（未加载的旧版本会从镜像加载它自己的权重）、切换、切回、下线（`POST …/{id}/retire`，删除它的向量库，要先确认）。检索因配置的模型和当前版本对不上而暂停时，页面用红色说明原因。

「入库任务」的「待清理图片」页签列出已从数据库删除、向量和文件还没删掉的图片（`GET /api/image-deletions`，最早删除的在前，最多列 50 张），「立即清理」逐批调用 `POST /api/image-deletions/process`（每批 50 条，有进展才继续，一次最多 10 批）；清理失败的留在队列里，在列表里写明原因，后台对账会定时重试。检索服务未就绪时按钮不可用。

### 信息提示（统一控件）

操作结果统一由一个控件提示：根组件里只挂一个 `<StatusOverlay />`（`src/shared/ui`），各页面发信号激活它，不再各自渲染提示条：

```ts
import { notify } from '../shared/ui'

notify.success('已保存。')                                              // 轻提示
notify.error(reason, { title: '保存失败' })                              // 弹窗
notify.warn('部分图片未添加', { details: issues })                      // 弹窗，details 逐条列出
notify.success('已保存。', { action: { label: '去同步', onClick } })     // action：onClick 或 href
```

- 成功（`success`）和普通提示（`info`）是顶部居中的**轻提示**：不挡操作、不抢焦点，可以同时显示最多 3 条；成功约 2.4 秒、普通提示约 3.6 秒后自动关闭，文字越长显示越久（最长 8 秒），鼠标停在上面时暂停，也可以点 × 关掉。有对话框打开时，轻提示显示在这个对话框里，不会被遮罩挡住。
- 警告（`warn`）和错误（`error`）用**弹窗**：模态 `<dialog>`，叠在已打开的对话框之上，看过、点「知道了」才关闭，原因和 trace_id 不会一闪而过。Esc、右上角关闭也会关掉它，点空白处也会关（`closable: false` 时不会）；关闭后焦点回到触发它的控件。同一时间只显示一个弹窗，后来的排在后面依次显示，相同的只显示一次。
- 可用 `duration` 改显示时长，`0` 表示不自动关闭。
- 字段校验（输入框下的红字）、加载失败加重试、入库按钮旁「为什么还不能开始」这类跟某个位置绑定的状态仍然显示在原处，不进提示。

## 已有接口约定

| 方法与路径 | 请求 |
| --- | --- |
| `POST /api/search/global/file` | 现网 Global 搜图（上传文件）：`multipart/form-data`，文件字段为 `file`；返回数量走 Query：`?search_num=10` |
| `POST /api/search/global/url` | 现网 Global 搜图（图片链接）：JSON：`{"img_url":"https://example.com/image.jpg","search_num":10}` |
| `GET /api/images/download` | Query：`url`，返回经验证的图片字节和实际图片 MIME 类型 |

两个 Global 接口只在图片输入方式上不同，共用同一套检索逻辑。前端单张及批量搜索使用上述新地址；旧 `/api/predict/searchImage_file`、`/api/predict/searchImage_url` 保留为兼容别名，不在 Swagger 中展示，参数和响应不变。

响应为 `{ "result": [...], "trace_id": "..." }`，上游没有结果时 `result` 为包含 `results` 数组的对象（`status=upstream_empty_response`）。`result[]` 的每一项和自建检索 `POST /api/search` 的 `items[]` 是同一张结果卡：顶层 `tags`（FlyB 为结果标题）、`description`、`original_url`、`similarity`（缺失时不显示虚构分数），其余在 `details` 里（缩略图在 `details.images[]`，来源网页、站点在 `details.page_url` / `details.site`），见契约 §6.1.1。Global 搜索返回的候选结果不等同于已入库图片。

`search_num` 是 FlyB 最多返回的条数（1–20），不传时用后端 `FLAB_CONFIG.DOC_COUNT`（当前 20）。前端在「现网 Global」单张搜索和批量搜索里用「返回数量」控件设置（默认 20，两种搜索共用一个设置）；后端不校验这个范围，所以前端只发 1–20 的整数。

## 验证与部署

本轮多图搜索、类别树下载与上传、场景配置往返的详细命令和验收预期见[验收说明](../docs/image-search-batch-config-acceptance.md)，自动化和真实页面的已执行结果见[验收记录](../docs/image-search-batch-config-verification-2026-11-15.md)。同图搜索的 FP32 分数微超 1 时，页面按浮点容差显示 `100.0%`。

```bash
npm test
npm run test:e2e
npm run build
npm run preview
```

浏览器测试默认使用本机安装的 Google Chrome，可通过 `PLAYWRIGHT_BROWSER_CHANNEL=msedge` 改用已安装的 Edge（PowerShell：`$env:PLAYWRIGHT_BROWSER_CHANNEL = 'msedge'`），自动启动或复用 `127.0.0.1:5173` 的开发服务。交互测试覆盖 URL/文件与批量搜索、多选与批量下载、代理回退、详情、筛选分页、错误与取消、导入队列、食材管理（类别树）及手机布局。本轮专项为 `e2e/config-transfer-search.spec.ts`，覆盖配置导出/预览/确认、prune 和批量搜索重试/停止。桌面与移动端截图输出到 `test-results/`，失败时保留 trace。测试中的网络响应使用受控模拟，目录选择使用内存替身，不访问真实后端或用户的保存目录；实际页面请求真实后端。构建输出为 `dist/`，可部署到静态 Web 服务。

生产环境需要 Web 服务将 `/api` 反向代理到后端，或在构建前设置 `VITE_API_BASE_URL` 并配置后端 CORS。Vite 的 `server.proxy` 仅用于开发，`npm run preview` 和静态产物不会自动代理 `/api`。环境变量在构建时读取，部署后修改需重新构建；接口设置也可在浏览器内覆盖。
