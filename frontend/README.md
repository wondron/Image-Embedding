# 食材图像工作台

React + TypeScript + Vite 前端。接入 Global 图像搜索，支持批量查询与结果下载；数据管理功能保留独立页面，入库与管理接口待接入。后端新增图片下载接口，用于浏览器无法跨域读取第三方图片时的回退。

## 本地运行

需要 Node.js 22.12+ 或 24，以及 npm。

```bash
cd frontend
npm install
```

Windows 如因本机 npm 缓存目录权限遇到 `EPERM`，可在 PowerShell 使用临时缓存：`npm.cmd install --cache "$env:TEMP\food-atlas-npm-cache"`，无需修改全局 npm 配置。

将 `.env.example` 复制为 `.env.local`，按需调整后端地址，然后启动：

```bash
npm run dev -- --host 0.0.0.0
```

打开终端显示的地址，默认 `http://localhost:5173`。后端需单独启动；开发服务器默认将 `/api` 转发到 `http://127.0.0.1:8320`，与当前后端 Compose 的端口映射一致。

| 配置 | 用途 |
| --- | --- |
| `VITE_API_PROXY_TARGET` | Vite 开发代理的后端地址，修改后需重启开发服务器 |
| `VITE_API_BASE_URL` | 可选的浏览器 API 地址；留空使用同源 `/api`，跨域需要后端允许 CORS |

界面中的接口设置可覆盖浏览器 API 地址，保存在当前浏览器的 `localStorage`。`VITE_*` 配置会进入前端构建产物，不应包含密钥。

## 当前功能

- 上传查询图片或输入图片 URL，调用已有搜索接口；显示请求状态、错误与空结果。
- 切换到“批量搜索”后可添加最多 30 张查询图片，每张不超过 15 MB。前端逐张调用文件搜索接口，显示各自进度、失败原因和结果；首张成功后自动展示结果，后续可点击队列中的“查看结果”切换。支持停止、继续和重试未完成任务，单项失败不影响后续图片。
- 支持网格／列表切换，展示结果图片和后端返回的相似度；图片按需加载，原图加载失败时按 large、medium、small、其他缩略图依次回退，详情弹窗按检索、预览、来源分区显示。Global 搜索阶段不会提前验证所有图片；仅开启 embedding 相似度过滤时，后端才按需获取图片计算分数。
- 当前结果集支持本地分页；只有接口提供类别时才能按类别筛选，不会从标题推测类别。
- 支持逐张选择、选择本页、选择全部结果和清空选择。跨页和切换网格／列表时保留选择；新的搜索或切换另一张查询图片的结果时清空选择，避免混合不同查询的结果。
- 点击“批量下载”可选择 ZIP 或保存到指定目录；按进度显示成功、失败记录，可停止或仅重试失败项。原图无法获取时按 large、medium、small、其他缩略图依次尝试，每批图片数据合计上限 200 MB，并附带 `results.json` 文件记录来源、相似度和失败原因。

### 保存位置与图片来源

支持目录选择的 Chrome、Edge 等浏览器可在 **HTTPS 或 localhost / 127.0.0.1** 页面使用“保存到指定目录”；实际支持情况由页面检测。普通 HTTP 局域网地址通常无法使用目录选择，仍可下载 ZIP。浏览器需要用户主动选择并授予目录访问权限；页面仅能显示目录名称，无法读取或展示完整本地路径。

每次目录下载会在所选位置新建独立的 `images-…` 子目录，避免覆盖已有文件。ZIP 的保存位置由浏览器下载设置决定；需要每次指定位置时，可启用浏览器的“下载前询问保存位置”。ZIP 下载成功表示文件已交给浏览器，请在下载列表中确认保存结果。

下载先尝试直接读取来源图片，跨域等原因失败时通过 `GET /api/images/download` 回退，再尝试缩略图。后端仅下载 HTTP(S)、80/443 端口的公网图片，每张最多 15 MB，检查每次重定向及实际图片格式；不访问内网、回环或元数据地址。代理不能绕过源站的登录、授权或防盗链限制；失败项仍可打开来源手动保存。

**使用代理功能需要重启包含本次代码的后端。** 现有旧镜像不会自动获得新接口，需重新构建或更新为包含新代码的镜像。数据管理相关后端功能未新增。

预留图片数据、上传与批量导入、入库任务、食材名称/类别/属性管理页面。文件队列和食材草稿仅用于浏览器本地交互，不会上传或写入后端；图片库、任务进度与失败记录等待真实接口接入。页面不使用模拟数据伪装搜索或入库成功。

## 已有接口约定

| 方法与路径 | 请求 |
| --- | --- |
| `POST /api/predict/searchImage_file` | `multipart/form-data`，文件字段为 `file` |
| `POST /api/predict/searchImage_url` | JSON：`{"img_url":"https://example.com/image.jpg"}` |
| `GET /api/images/download` | Query：`url`，返回经验证的图片字节和实际图片 MIME 类型 |

响应为 `{ "result": [...], "trace_id": "..." }`，也兼容 `result` 为包含 `results` 数组的对象。图片字段为 `image_url`，分数为 `similarity`（缺失时不显示虚构分数）；详情和缩略图来自 `details`。Global 搜索返回的候选结果不等同于已入库图片。

## 验证与部署

```bash
npm test
npm run test:e2e
npm run build
npm run preview
```

浏览器测试使用本机安装的 Google Chrome，自动启动或复用 `127.0.0.1:5173` 的开发服务。交互测试覆盖 URL/文件与批量搜索、多选与批量下载、代理回退、详情、筛选分页、错误与取消、导入队列、食材草稿及手机布局。桌面与移动端截图输出到 `test-results/`，失败时保留 trace。测试中的网络响应使用受控模拟，目录选择使用内存替身，不访问真实后端或用户的保存目录；实际页面请求真实后端。构建输出为 `dist/`，可部署到静态 Web 服务。

生产环境需要 Web 服务将 `/api` 反向代理到后端，或在构建前设置 `VITE_API_BASE_URL` 并配置后端 CORS。Vite 的 `server.proxy` 仅用于开发，`npm run preview` 和静态产物不会自动代理 `/api`。环境变量在构建时读取，部署后修改需重新构建；接口设置也可在浏览器内覆盖。
